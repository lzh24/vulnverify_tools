## 项目概述

### 核心目标

提供一个**统一的漏洞验证外部工具框架**,实现:

- **统一部署**: 所有工具运行在单个Docker容器(8000端口)
- **统一API**: RESTful接口,标准化的请求/响应格式
- **统一认证**: Bearer Token认证机制
- **动态加载**: 从`tools/`目录自动发现和加载工具
- **异步执行**: 基于FastAPI的异步架构,支持高并发

### 技术栈

| 组件 | 技术 | 版本 |
|------|------|------|
| Web框架 | FastAPI | 0.104.1 |
| ASGI服务器 | Uvicorn | 0.24.0 |
| 配置管理 | Pydantic Settings | 2.1.0 |
| HTTP客户端 | requests | 2.31.0 |
| Python | - | 3.9+ |
| 容器化 | Docker & Docker Compose | - |

## 核心组件详解

### 1. BaseToolService (抽象基类)

**文件**: `core/base_tool_service.py`

**职责**: 定义所有工具必须实现的接口规范

**核心方法**:
```python
class BaseToolService(ABC):
    def __init__(self, tool_name: str, tool_version: str):
        """初始化工具名称和版本"""

    @abstractmethod
    async def validate_params(self, params: Dict[str, Any]) -> bool:
        """参数验证 - 必须实现"""

    @abstractmethod
    async def _execute(self, params: Dict[str, Any]) -> Dict[str, Any]:
        """工具执行逻辑 - 必须实现"""

    async def execute(self, params: Dict[str, Any]) -> Dict[str, Any]:
        """公共执行入口 - 自动包装标准响应格式"""

    def get_health_status(self) -> Dict[str, Any]:
        """获取工具健康状态"""
```

**设计优势**:
- 强制一致的接口规范
- 自动包装标准响应格式
- 统一的错误处理机制
- 内置执行时间统计

### 2. ToolManager (工具管理器)

**文件**: `core/tool_manager.py`

**职责**: 工具的动态发现、加载和生命周期管理

**核心功能**:
```python
class ToolManager:
    def __init__(self, tools_directory: str = "tools"):
        """初始化并自动加载所有工具"""

    def _load_tools(self):
        """动态扫描tools/目录,导入模块并实例化工具类"""

    async def execute_tool(self, tool_name: str, params: Dict) -> Dict:
        """执行指定工具"""

    def get_tool_health(self, tool_name: str) -> Dict:
        """获取工具健康状态"""

    def list_tools(self) -> Dict[str, str]:
        """列出所有可用工具及版本"""
```

**动态加载机制**:
1. 扫描`tools/`目录下的所有子目录
2. 导入每个工具的`main.py`模块
3. 查找继承`BaseToolService`的类
4. 实例化工具对象并存储在内存中
5. 错误处理: 工具加载失败不影响其他工具

### 3. FastAPI应用 (main.py)

**职责**: HTTP服务端、路由、认证、CORS

**端点设计**:
| 方法 | 路径 | 功能 | 认证 |
|------|------|------|------|
| GET | `/` | 服务信息 | 否 |
| GET | `/health` | 整体健康检查 | 否 |
| GET | `/health/{tool_name}` | 单个工具健康检查 | 否 |
| POST | `/execute/{tool_name}` | 执行工具 | **是** (Bearer Token) |

**认证流程**:
```python
async def verify_token(request: Request):
    auth_header = request.headers.get("Authorization")
    provided_token = auth_header.split(" ")[1]
    if provided_token != config.tool_token:
        raise HTTPException(status_code=403, detail="Invalid token")
```

### 4. 配置管理 (config.py)

**职责**: 使用Pydantic Settings管理环境变量

```python
class ToolConfig(BaseSettings):
    tool_token: str              # 从环境变量TOOL_TOKEN读取
    log_level: str = "INFO"      # 默认值
    host: str = "0.0.0.0"
    port: int = 8000
```

## 现有工具清单

### 1. CurlExec (curl-exec)

**目录**: `tools/curl_exec/`

**功能**: 执行curl命令并返回原始响应

**API参数**:
```json
{
  "params": {
    "curl_args": ["-X", "POST", "http://example.com"],
    "timeout": 15
  }
}
```

**特性**:
- 并发控制 (MAX_CONCURRENCY=300)
- 自动添加默认User-Agent
- 超时控制
- 响应时间统计
- 错误处理

**使用场景**:
- HTTP请求测试
- 接口响应抓取
- 漏洞验证(如SSRF检测)

### 2. DnsLog (dnslog-service)

**目录**: `tools/dnslog/`

**功能**: DNS带外(OAST)检测工具

**API参数**:
```json
// 注册会话
{
  "params": {
    "action": "register",
    "domain_prefix": "test"
  }
}

// 轮询交互
{
  "params": {
    "action": "poll",
    "session_id": "session_12345"
  }
}

// 注销会话
{
  "params": {
    "action": "deregister",
    "session_id": "session_12345"
  }
```

**特性**:
- 会话管理
- 模拟随记DNS交互(用于测试)
- 记录交互历史

**使用场景**:
- XXE漏洞验证
- SSRF检测
- RCE带外验证

#### 2. 日志记录不完善

**问题**:
- `core/logger.py`存在但未使用
- 缺少结构化JSON日志
- 请求追踪(request_id)缺失

**建议**:
```python
# 实现JSONFormatter
import logging
import json
from datetime import datetime

class JSONFormatter(logging.Formatter):
    def format(self, record):
        log_obj = {
            "timestamp": datetime.utcnow().isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "request_id": getattr(record, "request_id", None),
        }
        if hasattr(record, "extra_data"):
            log_obj.update(record.extra_data)
        return json.dumps(log_obj)
```

#### 3. 工具隔离性不足

**问题**:
- 所有工具在统一进程中运行
- 工具崩溃可能导致整个服务不可用
- 无法限制单个工具的资源使用

**建议**:
- 方案A: 实现工具级别的超时和资源限制
```python
# 在ToolManager中添加超时保护
async def execute_tool_with_timeout(
    self, tool_name: str, params: Dict, timeout: int = 60
) -> Dict:
    tool = self.get_tool(tool_name)
    return await asyncio.wait_for(tool.execute(params), timeout=timeout)
```

- 方案B: 重构为多进程架构(长期方案)

#### 4. 并发控制存在但不够完善

**问题**:
- 只有`curl_exec`实现了信号量控制
- 其他工具无并发限制
- 全局无QPS限制

**建议**:
```python
# 在ToolManager级别添加全局限流
from ratelimit import limits
from functools import wraps

class ToolManager:
    @limits(calls=1000, period=60)  # 全局1000 QPS
    async def execute_tool(self, tool_name: str, params: Dict) -> Dict:
        ...
```

```python
from core.base_tool_service import BaseToolService
from typing import Dict, Any

class YourTool(BaseToolService):

    async def validate_params(self, params: Dict[str, Any]) -> bool:
        """验证参数"""
        required = ["param1", "param2"]
        return all(key in params for key in required)

    async def _execute(self, params: Dict[str, Any]) -> Dict[str, Any]:
        """执行业务逻辑"""

        return result
```
